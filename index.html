Method and code

An eval note on agent changes

You changedthe agent.Better, orjust lucky?

A single before/after run can't tell you. The same agent, rerun on the same cases, already disagrees with itself. Here is that disagreement, drawn from a real classification task.

Every point on this page is one of the 220 real calls. Amber matched the later ruling, grey did not. Scroll and they rearrange into the evidence.

The task

Classify a productunder the UStariff schedule.

The way a logistics agent would, before a shipment moves.

The answer key is public and already settled. US Customs periodically revises its own past classification rulings and publishes the correction. I pulled 22 of those revised rulings from the 2026 Customs Bulletins, stripped every case down to the product description, and kept the final tariff code as the gold answer. No private data, no synthetic labels, no case that carries its own answer in the text.

Independent research on public CBP documents. Not affiliated with or endorsed by CBP. Ruling numbers removed from the prompts.

Visual: 22 clusters of 10 points, one cluster per ruling, each point one call.

The setup

Two versions.Five reruns each.

Version A classifies directly. Version B adds one instruction most people would expect to help: work through the tariff interpretation rules in order before answering.

I ran each version five times over all 22 cases. Same model, same cases, nothing changed between runs except chance. 220 calls in total. Then the only question that matters before shipping: is B's lift bigger than the gap the agent produces against itself on a rerun?

Each row is one case, each column one rerun. Highlighted rows flip between runs on identical input. Hover a point for detail.

Visual: two grids of 22 rows by 5 runs. Version A has 6 cases that flip between runs, Version B has 5.

What the numbers show

The lift is smallerthan the wobble.

+4.5points, B over A on average
13.6 ptsB's swing against itself
−2.7 to 13.695% interval on the gap, in points: it crosses zero

Each band is how far that version swings from one rerun to the next. The bands overlap almost completely, and B's average improvement is smaller than B's own swing. Resample the cases ten thousand times and the gap still can't clear zero with confidence: about a 1 in 8 chance B is really no better, rising to 2 in 5 once you grade on the finer 6-digit code.

Both versions land near 40% because these are the rulings CBP itself went back and reconsidered, the genuinely hard cases. The finding is the gap between versions against the noise, not the absolute score.

Visual: per-run accuracy. Version A runs: 36.4, 31.8, 40.9, 36.4, 36.4 percent, mean 36.4, swing 9.1 points. Version B runs: 40.9, 40.9, 36.4, 50.0, 36.4 percent, mean 40.9, swing 13.6 points.

The trap

One run wouldhave shipped it.

Line up A's worst run against B's best and the change looks like a clear win: 7 against 11. That is the comparison a normal before/after gives you, and it is the exact trap. About 1 in 4 cases lands differently depending on the run, so the result you read is partly the draw you happened to get.

Visual: Version A's worst run matched 7 of 22 cases; Version B's best run matched 11 of 22.

The gate

Measure the noise.Ship only whatclears it.

  1. Rerun the current agent a few times on a fixed set and record how far it drifts from itself. That spread is the noise floor.
  2. Run the proposed change the same number of times. Compare distributions, not single scores.
  3. Ship only when the change beats the floor and its interval clears zero. Otherwise it is a coin flip wearing a number.

Pallet's pitch is that an agent never resolve the same exception twice. That promise lives or dies on telling a real gain from noise before it reaches a customer. This is the check that sits between a change and the ship button.

Honest limits

What this does not claim.

Small and single

22 cases, one frontier model, one task family. It sizes an effect, it does not certify the agent.

Noise left on

The model samples by default and exposes no switch to turn that off. Even forced to decode greedily, an agent that calls tools and retrieves is never fully repeatable. This is the variance production ships with, not a lab-quieted version.

The method is the point, not the model. Swap in Pallet's own agent, its own exception data, and a larger set, and the gate reads the same way.
